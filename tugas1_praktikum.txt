1. dokumen root adalah titik awal untuk mengakses dan menyajikan file dalam sebuah sistem atau aplikasi
2. Pada Apache Web Server yang berjalan di XAMPP di sistem operasi Windows, secara default, dokumen root (atau folder yang berisi file web yang akan diakses oleh pengguna) memang terletak di dalam direktori C:\xampp\htdocs. Ini adalah lokasi standar yang ditentukan oleh XAMPP untuk menampung file-file yang ingin disajikan melalui server web Apache.

Namun, tidak harus selalu terletak di C:\xampp\htdocs. Anda bisa mengonfigurasi Apache untuk menggunakan direktori lain sebagai dokumen root, jika diinginkan. Caranya adalah dengan mengedit file konfigurasi Apache.

Berikut adalah langkah-langkah untuk mengubah dokumen root Apache di XAMPP:

Buka file konfigurasi Apache:

File konfigurasi utama Apache di XAMPP dapat ditemukan di C:\xampp\apache\conf\httpd.conf.
Cari pengaturan DocumentRoot:

Buka httpd.conf menggunakan editor teks (misalnya Notepad).
Temukan baris yang berisi DocumentRoot. Biasanya akan terlihat seperti ini:
nginx
Copy
DocumentRoot "C:/xampp/htdocs"
Ubah path DocumentRoot:

Anda bisa mengubah path ini ke folder lain yang Anda inginkan. Misalnya:
nginx
Copy
DocumentRoot "D:/mywebsite"
Ubah directory directive:

Di bawah pengaturan DocumentRoot, Anda juga akan menemukan direktif <Directory>. Ubah path direktori ini juga sesuai dengan path baru yang Anda pilih:
php
Copy
<Directory "D:/mywebsite">
Simpan dan restart Apache:

Setelah Anda membuat perubahan, simpan file httpd.conf dan restart Apache melalui XAMPP Control Panel agar perubahan tersebut berlaku.
Dengan langkah-langkah ini, Anda dapat mengubah lokasi dokumen root Apache di XAMPP sesuai dengan kebutuhan Anda. Jadi, meskipun C:\xampp\htdocs adalah lokasi default, Anda memiliki fleksibilitas untuk memilih direktori lain sebagai dokumen root.
3.git init: Membuat repositori Git baru.
git clone: Menyalin repositori dari remote.
git remote: Mengelola remote repository.
git add: Menambahkan file atau perubahan ke staging area.
git commit: Menyimpan perubahan yang sudah di-stage ke repositori lokal.
git push: Mengirim commit dari repositori lokal ke repositori remote.
git checkout: Berpindah branch atau mengembalikan file ke versi sebelumnya.
Perintah-perintah ini adalah dasar yang sangat penting dalam penggunaan Git untuk pengelolaan kode sumber secara kolaboratif.
4.**GitHub** dan **GitLab** keduanya adalah platform berbasis Git yang memungkinkan pengelolaan repositori kode sumber secara online, tetapi ada beberapa perbedaan antara keduanya, baik dari segi fitur, penggunaan, dan orientasi platform. Berikut adalah perbedaan utama antara GitHub dan GitLab:

### 1. **Pemilik dan Fokus**
   - **GitHub**: 
     - **Pemilik**: GitHub dimiliki oleh Microsoft sejak 2018.
     - **Fokus**: GitHub berfokus pada kolaborasi sosial dan komunitas. Ini adalah platform yang paling populer untuk berbagi kode sumber dan proyek open-source. GitHub banyak digunakan oleh pengembang individu dan organisasi besar, dan sering digunakan untuk proyek-proyek open-source.
   
   - **GitLab**:
     - **Pemilik**: GitLab adalah platform open-source yang dimiliki oleh perusahaan GitLab Inc.
     - **Fokus**: GitLab lebih berfokus pada DevOps, pengembangan perangkat lunak secara end-to-end. Selain menyediakan hosting repositori Git, GitLab menawarkan alat-alat untuk Continuous Integration (CI), Continuous Deployment (CD), dan manajemen proyek secara keseluruhan.

### 2. **Fitur dan Alat DevOps**
   - **GitHub**:
     - Meskipun GitHub menawarkan alat CI/CD yang disebut **GitHub Actions**, GitHub tidak sepenuhnya berfokus pada seluruh siklus hidup pengembangan perangkat lunak.
     - GitHub lebih dikenal sebagai platform untuk kolaborasi kode, berbagi proyek, dan pengembangan open-source.
   
   - **GitLab**:
     - GitLab memiliki pendekatan yang lebih komprehensif untuk DevOps, dengan fitur built-in seperti **CI/CD**, **issue tracking**, **kanban boards**, **monitoring**, dan lainnya. GitLab bertujuan menjadi solusi all-in-one untuk manajemen pengembangan perangkat lunak.
     - GitLab menyediakan fitur seperti **Auto DevOps**, yang secara otomatis mengonfigurasi pipeline CI/CD, serta alat untuk manajemen siklus hidup perangkat lunak dari perencanaan hingga deployment.

### 3. **Model Hosting**
   - **GitHub**:
     - GitHub menawarkan hosting repositori berbasis cloud di **GitHub.com**. 
     - GitHub juga menawarkan **GitHub Enterprise**, versi self-hosted untuk organisasi yang ingin meng-host repositori mereka di server internal.
   
   - **GitLab**:
     - GitLab menawarkan dua opsi: **GitLab.com** (cloud hosting) dan **GitLab Self-Hosted** (self-hosted, di mana Anda dapat meng-host GitLab di server pribadi atau perusahaan).
     - GitLab sangat populer di kalangan organisasi yang menginginkan kontrol penuh atas infrastruktur mereka.

### 4. **Model Sumber Terbuka**
   - **GitHub**:
     - GitHub adalah platform proprietary, meskipun banyak proyek open-source yang dihosting di sana. GitHub sendiri bukan platform yang sepenuhnya open-source, meskipun ia memungkinkan proyek open-source untuk dihosting.
   
   - **GitLab**:
     - GitLab memiliki **edisi Community Edition** yang open-source dan dapat diunduh serta diinstal secara bebas. GitLab juga menyediakan versi **Enterprise Edition** dengan fitur tambahan untuk organisasi besar.

### 5. **Pengelolaan Proyek dan Issue Tracking**
   - **GitHub**:
     - GitHub menyediakan **GitHub Issues** untuk pelacakan bug dan tugas.
     - Fitur **Projects** di GitHub menawarkan manajemen proyek berbasis kanban untuk kolaborasi tim.
   
   - **GitLab**:
     - GitLab juga menyediakan fitur **Issue Tracker** yang sangat kuat, dengan kemampuan untuk melacak pekerjaan, membuat milestone, dan memetakan rencana pengembangan.
     - GitLab memiliki **Kanban boards** dan integrasi penuh dengan CI/CD, memungkinkan tim untuk mengelola proyek perangkat lunak secara lebih terorganisir dan efektif.

### 6. **Keamanan**
   - **GitHub**:
     - GitHub memiliki beberapa alat keamanan seperti **Dependabot** untuk memperbarui kerentanannya dan **Code Scanning** untuk mencari potensi kerentanannya dalam kode.
     - Fitur keamanan di GitHub berkembang pesat, tetapi umumnya lebih berfokus pada proyek open-source.
   
   - **GitLab**:
     - GitLab memiliki fitur keamanan yang lebih komprehensif, termasuk **Static Application Security Testing (SAST)**, **Dynamic Application Security Testing (DAST)**, dan **Container Scanning**.
     - GitLab juga mendukung **Security Dashboards** untuk membantu tim mengelola dan mengidentifikasi potensi masalah keamanan dalam kode mereka lebih baik.

### 7. **Pencarian dan Kolaborasi Sosial**
   - **GitHub**:
     - GitHub terkenal dengan aspek sosialnya. Pengguna dapat berinteraksi, memberikan bintang (stars), dan membuat **fork** repositori orang lain. Ini menjadikannya tempat yang sangat baik untuk proyek open-source dan kolaborasi komunitas.
     - GitHub memiliki **GitHub Pages** untuk hosting situs statis secara langsung dari repositori.
   
   - **GitLab**:
     - GitLab lebih terfokus pada pengelolaan pengembangan perangkat lunak dalam organisasi dan tim. Meskipun ada fitur untuk kolaborasi, GitLab tidak sepopuler GitHub dalam hal komunitas dan sosialitas.
     - GitLab tidak memiliki fitur seperti **GitHub Pages**, tetapi menyediakan layanan yang lebih terintegrasi dengan CI/CD.

### 8. **Integrasi dan Ekosistem**
   - **GitHub**:
     - GitHub memiliki ekosistem yang sangat besar dan mendukung berbagai layanan dan alat pihak ketiga. Selain itu, banyak perusahaan yang menggunakan GitHub untuk berbagi proyek open-source mereka, dan GitHub memiliki pasar aplikasi yang kaya (GitHub Marketplace).
   
   - **GitLab**:
     - GitLab menawarkan integrasi yang lebih mendalam dalam ekosistem DevOps-nya sendiri, dengan alat seperti **GitLab CI/CD**, **GitLab Container Registry**, dan lainnya. Semua fitur ini sering terintegrasi lebih baik di dalam platform GitLab itu sendiri.

### 9. **Pricing**
   - **GitHub**:
     - GitHub menyediakan **versi gratis** dengan batasan tertentu, tetapi untuk fitur tambahan, seperti private repositories, Anda harus memilih paket berbayar.
     - GitHub memiliki harga yang lebih terjangkau bagi individu dan tim kecil.
   
   - **GitLab**:
     - GitLab juga menyediakan **versi gratis** (Community Edition) dan **versi berbayar** (Enterprise Edition) dengan fitur tambahan seperti manajemen proyek yang lebih maju dan dukungan premium.
     - GitLab menawarkan lebih banyak kontrol atas fitur di lingkungan self-hosted.

### Ringkasan Perbandingan:
| Fitur                      | **GitHub**                                    | **GitLab**                                       |
|----------------------------|-----------------------------------------------|--------------------------------------------------|
| **Fokus**                   | Kolaborasi kode, open-source, komunitas       | DevOps, CI/CD, manajemen siklus hidup perangkat lunak |
| **Pemilik**                 | Dimiliki oleh Microsoft                       | Dimiliki oleh GitLab Inc.                       |
| **Hosting**                 | Cloud (GitHub.com) dan self-hosted (GitHub Enterprise) | Cloud (GitLab.com) dan self-hosted (GitLab CE/EE)|
| **CI/CD**                   | GitHub Actions                                | CI/CD yang lebih lengkap dan terintegrasi        |
| **Repositori**              | Publik dan private                            | Publik dan private, lebih banyak fitur untuk pengelolaan proyek |
| **Komunitas**               | Sangat besar, fokus pada proyek open-source   | Fokus lebih pada organisasi dan tim DevOps       |
| **Keamanan**                | Dependabot, Code scanning                    | Fitur keamanan lebih lengkap (SAST, DAST, dll.) |
| **Pricing**                 | Gratis, paket berbayar untuk tim dan enterprise | Gratis (Community Edition), Enterprise Edition dengan fitur tambahan |

Kedua platform memiliki keunggulannya masing-masing, dan pilihan antara GitHub atau GitLab biasanya tergantung pada kebutuhan spesifik tim atau organisasi. GitHub lebih populer untuk proyek open-source dan kolaborasi sosial, sementara GitLab sering dipilih oleh tim yang membutuhkan solusi DevOps terintegrasi dan kontrol lebih dalam pengelolaan siklus hidup perangkat lunak.
